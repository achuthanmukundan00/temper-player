# v0.2.0 — Library management and reliability

## What's new

- Confirmed single/bulk removal from the library. **Original audio files are never deleted.** Playlist/history membership and playback queues are reconciled.
- File, folder, and drag-and-drop imports share one cancellable pipeline with deduplication, format validation, and clear results.
- Manage imported folders, rescan them, inspect missing files, and explicitly remove missing library entries.
- Search/sort the library, select ranges or multiple tracks, and batch-edit library title/artist/album metadata.
- Safer playlist creation, renaming, clearing, deletion, and bulk membership actions, including compact-window controls.
- Full queue editing with fixes for shuffle order, duplicate occurrences, current-track removal, and failed-file/end-of-queue handling.
- Checked SQLite transactions, history-preserving reimports, atomic artwork persistence, and visible failure reporting.
- Isolated regression tests, macOS CI, a user guide, and a versioned packaging script.

## Download and upgrade

Download **TemperPlayer-v0.2.0.dmg** and **SHA256SUMS** from this release.

- **Apple silicon; macOS 14 or newer.** No Intel binary is published in this release.
- Verify the download: `shasum -a 256 -c SHA256SUMS` with both files in the same directory.
- Quit TemperPlayer and back up `~/.temperplayer` before upgrading. Drag the app into Applications, replacing the old app. Existing library data, preferences, and original audio files are kept separately from the app bundle.
- The bundle includes its matching Zig dylib and does not require Zig, Xcode, or the source checkout to run.
- **Ad-hoc signed only: not Developer ID signed or notarized.** macOS may block the first launch. Only if you trust the download, approve it via **System Settings → Privacy & Security → Open Anyway**. Do not disable Gatekeeper globally.

For rollback, quit the app and restore your previous app bundle. If restoring a pre-upgrade database, restore the whole backed-up `~/.temperplayer` directory while the app is closed; this also discards library changes made since that backup. Restoring the app alone does not restore library data.

## Validation and limits

The automated suite covers database failures/rollback, imports, artwork, library actions, selection/search, and queue/shuffle invariants. Release checks include a release build, bundle signature/linkage checks, DMG checksums, and isolated startup.

This is a usability/reliability release, **not a claim of exhaustive production certification**. Developer ID/notarization, clean-account Gatekeeper testing, extended device/sleep-wake playback testing, and large-library profiling remain open. See the [release checklist](https://github.com/achuthanmukundan00/temper-player/blob/v0.2.0/docs/release-checklist.md).

Current boundaries: mono/stereo audio only; removal has no Undo and does not trash source files; metadata edits do not write embedded tags; no automatic folder watching, relinking, automatic backups, cloud sync, or persistent play queue.
